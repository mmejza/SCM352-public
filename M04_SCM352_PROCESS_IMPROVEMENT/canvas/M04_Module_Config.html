Canvas Setup Procedures

iFrame embed · Gate 2 Q1 version groups · Gate 1 retake cooldown workaround

A — App / Viewer iFrame Embed (Items 5, 6, 7, 8, 9)
ℹ️
Apps and the slide viewer are hosted HTML files. Use Canvas External URL items to link out, or embed inline via a Canvas Page with the iFrame template below.
Step 1. In Canvas Modules → click + → select External URL. Paste the hosted file URL. Title it exactly as the module item name (e.g., "App 1 — Efficiency Metrics Identifier").
Step 2. Check Load in a new tab unless inline embedding is required. For inline embedding, create a Canvas Page, switch the editor to HTML mode, and paste the iFrame template:
<p><iframe
  src="[HOSTED_FILE_URL]"
  width="100%"
  height="720"
  style="border:none;overflow:hidden;"
  allowfullscreen="true"
  webkitallowfullscreen="true"
  mozallowfullscreen="true">
</iframe></p>
Replace [HOSTED_FILE_URL] with the actual URL. Height 720 works for all M04 apps. Use 800 for the slide viewer.
B — Gate 2 Q1 Version Groups Setup (Question Group Method)
⚙️
Canvas Classic Quizzes. Q1 has 4 versions (A–D). Use a Question Group to hold all 4 and pick 1 per student, then verify ID-to-version alignment using the quiz statistics export.
Step 1. In the Gate 2 quiz editor, click New Question Group.
Step 2. Name it Q1 – Efficiency Metrics Chain (Versioned). Set Pick = 1, Points = 20.
Step 3. Add all 4 version questions to the group from the question bank. Label each question with its version letter (e.g., "Q1-A — Outpatient Lab").
Step 4. After the quiz closes, export the Student Analysis CSV: Quiz → Statistics → Student Analysis. This shows which version (question) each student received.
Step 5. Cross-check: confirm the assigned version matches the ID-last-digit rule (0–1→A, 2–3→B, 4–5→C, 6–9→D). For any mismatch, manually apply the correct answer key for that student. The CSV is the authoritative version record — do not rely on student self-report.
C — Gate 1 Retake Cooldown (Canvas Limitation & Workaround)
⚠️
Canvas Classic Quizzes has no native timed cooldown between attempts. The 24-hr cooldown policy must be enforced manually by the instructor.
Setup: Configure Gate 1 with Allowed Attempts = 1. Students who score <80% will see the quiz locked and must contact you to request a retake.
Granting a retake: SpeedGrader → click student → "Moderate This Quiz" → Extra Attempts +1. Only grant after confirming ≥24 hours have elapsed since the first attempt (check the attempt timestamp in SpeedGrader).
Tracking: Maintain a retake log (spreadsheet): student name, first-attempt time, retake-granted time, second-attempt score. Graders must check this log before granting any retake to avoid inconsistent enforcement.
Edge case — early request: If a student emails within 24 hrs of failing, reply with the exact date/time they become eligible. Do not grant the attempt early.

Q7 — Financial Impact of Process Improvement (15 pts, FIXED for all students)

Scenario: Two urgent care clinics (Clinic A and Clinic B) share identical 3-step process: S1=4 min, S2=10 min (bottleneck), S3=5 min. Workers: 3 at $22/hr each. Revenue=$55/patient, VC=$12/patient, Fixed=$60/hr. Vendor upgrade reduces S2 from 10→8 min. Clinic A: demand=5/hr (demand-constrained). Clinic B: demand=8/hr (capacity-constrained).

ClinicBefore: flow rate + profitAfter: flow rate + profitChangeKey teaching point
A (demand-constrained)FR=5/hr; Profit=5×43−66−60=$89/hrFR=5/hr (unchanged); Profit=$89/hr$0 (0%)Demand caps flow rate; more capacity = no revenue gain
B (capacity-constrained)FR=6/hr; Profit=6×43−126=$132/hrFR=7.5/hr; Profit=7.5×43−126=$196.50/hr+$64.50 (+48.9%)Bottleneck improvement directly increases flow rate and revenue

⚠️ Most common error: Student calculates Clinic A profit increasing because new process capacity is 7.5 > 5. Correct reasoning: capacity > demand means demand is still the binding constraint — flow rate stays at 5.

Step 4 — During-Module Monitoring (est. 30 min total)
Day 3
Pull Gate 1 completion report. Chapter 4 has the most complex reading in the first four modules — Section 4.6 (Tables 4.1 and 4.2) is particularly dense. Students with 0 Gate 1 attempts by Day 3 have effectively no path to completing the module on time. Send a targeted nudge to those students only; do not broadcast to the whole class. Nudge message should reference the Day 6 deadline, not just the Gate 1 itself.
Day 4
Scan discussion initial posts for two issues. (1) Business naming: Watch for posts that describe a process without identifying a specific business by name — apply the 10-pt naming deduction per the rubric. (2) Demand-constrained logic in Part 4: Posts that recommend a bottleneck improvement without distinguishing between capacity-constrained and demand-constrained are missing the core LO4-6 skill. Leave a brief comment pointing to the distinction — this often pre-empts the same error in Gate 2 Q7 and Case Part 5.
Day 6 (after Gate 2 closes)
Export quiz statistics. Watch for three error patterns: (1) Q1 cycle time error — students who use process capacity (rather than demand-limited flow rate) as the cycle time denominator for demand-constrained versions. (2) Q5 unnecessary reassignment — the packaging line problem is intentionally demand-constrained; students who blindly reassign the bottleneck activity without first checking demand vs. capacity are falling into the same trap as Table 4.2. (3) Q7 Clinic A profit increase — most common Q7 error; student correctly computes new process capacity but forgets that demand (5/hr) is still the binding constraint. If >15% of class misses Q7, address in an announcement before Case grading begins.
Post-module
Grade Discussion initial posts after M05 module closes. Discussion posts are due at M05 close — do not grade before then. Use M04_Discussion_Rubric.html in SpeedGrader. Estimated 2–4 min per submission. If a student's post identifies a demand-constrained business (Part 4 recommends no improvement or recommends against investment), confirm they used the correct framework — this is full credit, not an error.
