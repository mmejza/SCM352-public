Project Management — The Longest Path to Failure

Every complex project failure has the same early symptom: someone started an activity before its predecessor was done. The tools in this module exist to prevent that from happening — by making hidden dependencies explicit and computing which activities have no room to slip.

In 1994, Denver International Airport opened its new automated baggage system — a marvel of engineering that was supposed to move luggage across 21 miles of tunnels at 19 miles per hour. Instead, the system mangled bags and sent suitcases to entirely wrong gates. It took an additional 16 months and $560 million beyond the original budget to get it partially working. The airport itself opened two years late.

What went wrong was not a technology failure. It was a project management failure. Developers began building the software before the terminal's mechanical design was finalized — so the system specifications kept changing as the physical building changed around it. Activities that were assumed to be independent turned out to depend on each other. Critical path activities were delayed, and because the entire project hung on those paths, every delay cascaded into another.

This module gives you the tools to prevent that. You will build dependency matrices that make hidden relationships explicit, apply the Critical Path Method to compute the minimum possible project duration, use Gantt charts for project control, and determine how activity delays propagate through the network to affect the overall deadline.

This is the final module of SCM 352. Everything you have learned this semester — from process flow to inventory to quality control — appears inside complex projects. A hospital EHR rollout requires capacity planning (M02–M04), inventory of hardware (M08–M10), quality monitoring (M07), and supplier coordination (M11–M12). Project management is the framework that coordinates all of it. The Case Analysis in this module is your final Riverside Health System deliverable.
