Discussion: Projects That Went Wrong

Real project failures are almost always dependency failures — an assumption that activity X would be done before activity Y began, that turned out to be wrong. Connect a real-world project failure to the CPM and PM tools from this module.

The Prompt — Five Parts · Address All Five in Your Post

Aim for approximately 400–550 words. All five parts must be addressed to earn full credit.

①
Identify the project and its failure. Name the project, the organization or context, and the approximate time period. Briefly describe what the project was supposed to accomplish and what went wrong. Cite at least one external source (news article, academic article, government report, or industry report). Do not use Wikipedia as your primary source.
②
Apply dependency matrix thinking. Identify at least two activities from the project where the dependency assumption broke down — where an activity began before its predecessor was actually complete, or where a dependency that should have existed was not recognized. Explain the consequence: which downstream activity was affected, and how did the failure propagate?
③
Apply critical path thinking to the failure. Based on what you know about this project, identify the activities you believe were on the critical path — the sequence with zero slack where any delay propagated directly to the project deadline. Then identify at least one activity that was treated as non-critical (assumed to have slack) but whose delay ended up affecting the project. Explain how the team's understanding of which activities were "safe to delay" turned out to be wrong — and what a properly constructed CPM analysis might have revealed before the crisis began.
④
Connect to one additional OM tool from SCM 352. Choose any concept, tool, or framework from Modules 1–12 of this course that is relevant to this project failure. Explain the connection: if that OM tool had been applied correctly, how might the failure have been avoided or reduced in severity? Be specific — name the tool and state the mechanism of intervention.
⑤
State the correctable root cause. In one or two sentences: what is the single most actionable root cause of this failure that a project manager could have addressed before the project began? Distinguish between a root cause (something that, if fixed, would have prevented the failure) and a symptom (something that appeared because of the failure).
Target length: approximately 400–550 words. You will not be penalized for going slightly over. Posts under 300 words are unlikely to address all five parts in sufficient depth to earn full credit. Write for a reader who has taken this course — you do not need to define basic CPM terms, but do explain specifically how they apply to your project.
