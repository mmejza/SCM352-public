AON Network — Construction Rules
Activity-on-Node: each box is an activity; each arrow is a dependency
Rule 1 — One Box Per Activity

Each activity gets exactly one box showing its letter, description, and duration. Boxes do not represent start/end of an activity — the activity is the box.

Rule 2 — Arrows = Dependencies

An arrow from A to B means "B cannot start until A is complete." The arrow direction is always left to right. Arrow length has no meaning.

Rule 3 — START and END Nodes

Add a START node (oval) on the left. Every activity with no predecessor connects from START. Add an END node on the right. Every activity with no successor connects to END.

Rule 4 — Merge Points (Multiple Predecessors)

When activity E requires both C and D, draw both arrows: C→E and D→E. Drawing only one arrow is the most common AON construction error.

Why it matters: Missing the D→E arrow makes the forward pass compute EST(E) = ECT(C) instead of max(ECT(C), ECT(D)). This gives an incorrect — and too early — start time.

Rule 5 — Split Points (Multiple Successors)

When activity A feeds both B and C, draw two arrows: A→B and A→C. Both activities can start as soon as A finishes — they do not depend on each other.

A split point says: "A's completion unlocks multiple downstream activities simultaneously." A merge point says: "Multiple completions are all required before this activity can begin."
