Project Description

A software team is building a new patient scheduling system. The project starts with requirements analysis. Once requirements are done, two parallel workstreams begin: database design leads to backend development, while UI/UX design leads to frontend development. Integration testing cannot start until both the backend and frontend are complete. System deployment follows integration testing.

Building the Dependency Matrix

A (Requirements): No predecessor — starts immediately.

B (Database design): Requires A. Cannot start until requirements are defined.

C (UI/UX design): Requires A. Parallel to B — independent of database design.

D (Backend development): Requires B (database design). True dependency.

E (Frontend development): Requires C (UI/UX). True dependency.

F (Integration testing): Requires both D and E — merge point.

G (System deployment): Requires F.
